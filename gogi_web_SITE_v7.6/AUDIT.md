## 最終監査で修正した重要項目

### 公開契約

- 「提示者を攻撃しない」「提示者を防御」のように条件文から提示者を逆算できる旧方式を廃止。
- 5条件をすべて汎用の指定色方式へ統一: 攻撃 / 攻撃しない / 防御 / 回復 / 告発。
- 提示者ID・参加者ID/色をクライアントへ送らず、条件対象色と1人あたり報酬だけを公開。
- 自動参加・提示した同ターン判定・複数同時契約・第15ターン報酬2倍を維持。
- 回復契約を正式追加。実回復量が0でも、有効な回復カードを指定色へ使用した事実で達成判定。
- 告発済み対象は通常告発・2倍告発・公開契約告発の候補から除外。

### 防御

- 同じ対象を複数人が通常防御し、その対象に有効な攻撃が1以上あり通常防御で1以上を防いだ場合、**防御人数が攻撃数を上回っても防御参加者全員を成功扱い**に統一。
- 自分防御+10P、他人防御+15P、完全防御は自分専用というルールと表示を一致。

### CP

- チャット以外の主要機能を正式利用: 通常/特殊行動、秘密目標、購入、交換、公開契約、1位予想、五戯チップ。
- 残りターン、秘密目標の達成可能性、本人のHP/P/手札、本人が得た偵察情報、公開情報、公開契約、終盤順位を統合して判断。
- 交換は固定パターンではなく、カード限界価値・HP・秘密目標・終盤順位・相手別の承認/拒否履歴・同一提案の反復ペナルティを使う。CP宛の提案は放置せず承認/拒否し、条件によってカウンター提案も行う。
- 1位予想は自己固定を廃止し、全候補の推定勝率と倍率/期待値を比較。
- 2倍カードは攻撃/防御/偵察/告発/回復ごとに個別評価。
- 公開契約の実参加人数、推定カード保有可能性、ライバルへの外部利益まで評価。
- 古い偵察情報を永久確定扱いせず時間減衰。
- CPがサーバー内部の他人の現在HP、非公開P、秘密目標、未偵察手札、内部publicEvents、他人の準備状態を直接読んで戦略判断する経路を除去。人間プレイヤーが取得可能な範囲の情報を基準にした。

### 交換・購入・待機

- 交換カード枚数を1〜99枚で指定可能。提案者側はエスクローし、拒否・取消・期限切れで返却。
- 同一相手/複数相手へ複数提案可能という現行仕様を維持。
- 通常/特殊購入は所持Pの範囲で回数制限なし。旧1回制限時代の `specialPurchased` / `normalPurchasedTurn` 状態を削除。
- CP補充開始は参加中の人間全員同意制。
- 待機室切断は即退出方式へ統一し、未使用となった旧待機室再接続猶予定数を削除。


### 五戯チップ残高の信頼境界

- クライアントが送る `chipBalance` を参加判定に使う方式を廃止。localStorage改変で任意残高を申告できる穴を閉じた。
- browserId別のサーバー内台帳を正とし、公開/プライベート参加時の残高不足判定、開始時の差引、終了時賞金をサーバー側で同期する。
- 「所持0のとき100,000チャージ」もサーバー側で0判定し、対戦参加中はチャージ不可。
- ブラウザ側localStorageは表示キャッシュに限定。偽の高額残高を入れても参加前同期でサーバー値へ戻る。
- 恒久アカウント/DBなしという仕様上、browserId削除による新規扱いとサーバー再起動後の初期化までは防げない。

### 情報保護・通信

- サーバーをゲーム状態の正とし、クライアント入力を再検証。
- `phaseSeq` で古い操作を拒否し、経済操作は `opId` でACK再送時の二重処理を抑止。
- 公開結果を廃止し、各ターン中は本人向け結果だけ配信。サーバー内部の詳細ログはクライアントへ送らない。
- 個別チャットは当事者だけに配信。
- CSP / HSTS(本番) / frame拒否 / no-referrer / Permissions-Policy / Origin制限 / Socket接続上限 / 入力長 / 操作頻度制限を確認。

### 境界値・障害耐性

- 公開契約の金額ヘルパーを追加硬化し、`NaN`・負値・不正上限・不正倍率を安全に拒否/0値化。異常値が返却額へ `NaN` として伝播しないようにした。
- 五戯チップの不正刻み・残高不足をゲーム状態変更前に拒否する境界テストを追加。
- カード指定タイムアウトの防御/偵察/告発自動補完、無効固定対象、壊れた入力との組合せを追加回帰テストで固定。
- 秘密目標本体が有効で `secretState` だけ欠損したケースも自動修復する経路を直接検証。
- `npm run check` の対象へ `src/contracts.js` と `scripts/stress.js` を追加し、配布後の自己検証範囲を拡張。

### UI・キャッシュ・文書

- iPhone縦画面を含むレスポンシブ表示で主要画面の横はみ出しを確認。
- 購入画面は所持枚数ではなく購入対象と価格中心の表示を維持。
- 公開契約の提示者/参加者表示を撤去。
- 公開契約の条件対象に提示者自身の色も指定可能。提示者本人は報酬参加者から除外するため、自己契約で自分へ報酬を戻す抜け道は作らない。
- カード購入価格を全種類5P引き下げ（通常10/10/10/20/30P、特殊40P）。初期回復は1枚を維持。
- サーバー、クライアント、HTML/CSS/カード資産のビルド識別子を `20260913-complete-final10-icon` に統一。
- 準備OK中の人間にも交換提案を受信可能にし、受信時は準備OKを自動解除して承認/拒否後の再準備を要求。
- 公開契約は準備OK中でも通知するが自動参加のため強制解除しない。交換・公開契約通知はトーストでも表示。
- README / RULES / RULE_DECISIONS / DEPLOY / AUDITを現仕様へ統一し、過去の更新メモは最終配布から除外する。

## 性能・構造

- 5人固定・15ターンのため、1ターン解決は小規模なメモリ内処理。
- チャット履歴、内部ログ、偵察履歴、操作ID履歴には上限がある。決済済み公開契約もライブ配列から除去し、件数無制限仕様でも試合中メモリを不要に積み上げない。五戯チップ台帳も最大件数＋30日未使用掃除で無制限増加を防ぐ。
- カード画像はリビジョンURL + 長期キャッシュ。HTML/JS/CSSはno-store運用で旧画面残留を抑止。
- 現行は1 Nodeプロセスのメモリ状態を前提とする。共有状態ストアなしの水平分散は行わない。

## 構造上または環境上の残る限界

- 五戯チップは**無料・換金不可・恒久アカウントなし**のカジュアル機能。localStorageの残高改変はサーバー台帳化で無効化したが、browserId自体を消して新規扱いにする行為・別ブラウザ/別端末・サーバー再起動をまたぐ恒久残高は保証できない。実価値を持たせるには認証 + サーバー永続DBが必要。
- 状態は単一Nodeプロセスのメモリ保持。サーバー再起動時の進行中試合・五戯チップ台帳の復元、複数インスタンス同期は未実装。
- この監査環境ではExpress / Socket.IO依存パッケージを取得できず、実サーバーを起動した5ブラウザSocket E2Eと `npm audit` は未実施。公開前にネット接続可能な本番相当環境で実施する。
- 実iPhone/Android/PC複数台、通信瞬断、OSバックグラウンド、省電力の全組合せは自動検証で完全網羅できない。

以上の限界は「既知のコード不具合」ではなく、現在の無料・アカウントレス・単一プロセス設計または監査環境の境界である。
