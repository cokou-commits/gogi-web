# 五疑戦 v7.6 — LIMIT MAX 再監査（2026-09-11）

## 結論
今回の再監査でも小さな改善余地が残っていたため修正した。ゲームルール・得点・カード効果は変更していない。
単一Node.jsプロセス／単一Renderインスタンスという現アーキテクチャのまま、安全に行えるコード側改善はこれで実用上の限界に近い。

## 今回追加で修正した項目

1. サーバーがクライアントへ返さない古いチャット/ログまで保持していたため、保持上限を表示上限と統一。
   - チャット: 500件保持 → 160件
   - ログ: 180件保持 → 80件
   - 多数ルーム稼働時のメモリ浪費を削減。
2. 操作IDの重複記録上限を96件 → 64件へ縮小。即時ACK再送に必要な範囲を残しつつプレイヤー単位メモリを削減。
3. チャット等の入力正規化を強化。
   - Unicode NFC正規化
   - 双方向制御文字に加え、不可視の方向指定/ゼロ幅偽装文字を除去
   - 1行UIに対して改行/タブを大量送信する表示崩しを空白へ正規化
   - 絵文字のZWJは保持
4. 招待リンクのルームコードを `?room=` から `#room=` へ変更。
   - 新規招待コードがHTTPリクエスト/Refererへ送られない。
   - 旧 `?room=` リンクも互換読込する。
   - Referrer-Policyも `no-referrer` へ強化。
5. カード画像のロードが遅い/失敗した場合もカード名が見えるフォールバック表示を追加。
   - 会話・行動選択中に画像取得失敗が操作不能につながらないようにした。
6. ローカル監査用スクリーンショット約1MBを配布ZIPから削除し、Docker除外規則も追加。
7. 公開ドキュメントに残っていた「東京リージョン」記述を、現在のRender運用に合わせ「RenderならSingapore」へ統一。
8. 上記と、軽量state受信時にカード定義カタログを保持する処理を回帰テスト化。

## 残る限界

ここから先は「小修正」ではなく実環境/アーキテクチャ領域。

1. Render本番で異なる端末・回線の人間5人による15ターン完走E2E。
2. 本物のSocket.IOクライアントによる同時接続/負荷試験。
3. `RULE_DECISIONS.md` 27項目のゲームデザイン最終決定。
4. npm registryへ接続できる環境で `npm install` / `npm audit` / `package-lock.json` 生成。
5. 大規模化時のRedis等による共有状態、複数インスタンス、再起動復元。
6. 公開匿名サービスへの大規模L7/DDoSはアプリ内制限だけでは完全防御できないため、Render/外部WAF等のインフラ対策。

## 限界判定

現構成を保ったままのロジック修正、入力防御、ブラウザUI、メモリ削減、配布ノイズ除去については実用上の限界に到達。
次に品質を大きく上げる作業はコードの微修正ではなく、5人実戦E2Eと本番Socket負荷試験である。
