# 五疑戦 (GOGISEN) — Web版 v7.6 / 完全完成版

5人制・15ターンのオンライン心理戦カードゲーム「五疑戦」の現行実装です。2026-09-13の完全完成版最終監査ビルドで、ルール・UI・通信・再接続・秘匿情報・経済操作・終了処理をサーバー主導で統一しています。

> CPは正式実装です。チャット以外のゲーム機能（行動、秘密目標、購入、交換、公開契約、1位予想、五戯チップ）を使用します。外部AI/APIは使用しません。
> CP最高戦略版では、残りターン・秘密目標進捗・偵察履歴・公開契約・本人に公開される順位・得点期待値・生存価値を統合して行動します。対戦相手の非公開ポイント/秘密目標/未偵察手札/準備状態を直接読む処理はありません。
> 1位予想は自己固定ではなく、既知情報から全5色を比較します。明確な本命がいれば本命へ、拮抗時は推定勝率に応じて他プレイヤーにも賭けます。

## 現行仕様の要点

- 5色: 赤 / 青 / 黄 / 緑 / 紫
- CP補充は参加中の人間全員の同意後に空き枠をCPで埋めて開始。1人だけの操作では他の人間参加者を強制開始しない
- 初期HP5、最大HP5、HP0で脱落、復活なし、初期0P
- 会話＋行動選択は最大10分、結果確認は最大1分
- 通常カード: 攻撃 / 防御 / 偵察 / 告発 / 回復
- 特殊カード: 完全防御 / 無効 / カード指定 / ポイント泥棒 / 2倍
- カード指定は「相手・通常カード・使用対象」まで指定。相手が指定カード未所持なら失敗し、カード指定は使用者へ返却
- カード指定の固定対象が次ターンまでに無効になった場合は別対象へ振り替えず行動なし。指定通常カードは消費しない
- 完全防御 / カード指定 / ポイント泥棒は本人のターン結果に成功・失敗を表示
- カード指定で固定した通常カード＋対象が成功した場合、その成功得点は指定者へ入る。告発失敗などの減点は実行者本人
- 通常防御は自分または他の生存者を守れる。対象に有効な攻撃があり通常防御で1以上防げれば、同じ対象を守った全員が成功（攻撃数より防御人数が多くても全員成功）。自分への防御成功+10P、他人への防御成功+15P。完全防御は自分専用
- 他人への回復でHPを実際に1以上回復した場合+10P
- 回復は自分または他の生存者を+2、2倍併用時は同じ対象を+4
- 購入価格: 攻撃10 / 防御10 / 偵察10 / 告発20 / 回復30 / 特殊40P
- 通常カード購入は各ターン回数制限なし。特殊カード購入も所持ポイントの範囲で回数制限なし
- 告発は脱落者も対象に選択可能（自分自身は不可）
- 独立したポイント譲渡・カード譲渡は廃止。承認制の交換へ統一。カードは1〜99枚で枚数指定可能
- 公開契約は20P刻み。条件対象には提示者自身の色も指定可能。提示と同時に条件上参加可能な生存者が自動参加し、提示者・参加者の色は非公開。通常報酬は達成者1人あたり使用P÷4、第15ターン判定は2倍。余剰分は返却。提示件数制限なし（同一ターン・同時複数件可）。報酬額は契約一覧・通知で全員へ表示
- 1位予想は第3/6/9ターンのいずれか1回。10倍 / 5倍 / 2.5倍
- 1位予想は試合中非公開、試合終了時に全員分を公開
- 五戯チップは無料配布のみ。課金購入・譲渡・換金・景品交換なし
- 五戯チップは初期100,000。所持0のときだけ100,000チャージ可能。日付による自動配布なし。残高の正はサーバー内台帳で、ブラウザlocalStorageは表示キャッシュのみ。公開マッチは0/100刻みで同額の5人だけをマッチング
- プライベートは部屋主の設定額を全員へ強制し、不足している参加者は入室不可
- 五戯チップ賞金枠は最終順位1位2.5倍＋1位予想成績1位2.5倍。同率は各賞金枠を均等分配。予想的中者/参加者がいなければ予想枠は第2順位発表の1位へ配分
- 秘密目標10種、報酬25P
- 第5/10/15ターン開始時に生存者へ+5/+10/+15P。いずれも2倍なし
- 第15ターン終了まで生存で+50P。2倍なし
- 第15ターンは攻撃成功・防御成功・告発成功/失敗・完全防御等の新規得点/減点のみ2倍
- 各ターンの公開結果はなし。本人には成功/失敗、偵察、HP純増減、ポイント純増減だけ表示
- BGMなし。SE・通知音のみ。全体/個別チャット、交換、公開契約に通知あり
- 個別チャットは色ごとに履歴を分離
- 最終画面は賭け判定前順位 → 1位予想結果 → 正式最終順位を追加操作なしで表示

詳細な確定ルールは `RULES.md`、最終決定事項は `RULE_DECISIONS.md` を参照してください。

## 実装上の保護

- サーバーをゲーム状態の正とし、クライアント入力を検証
- 五戯チップ残高もクライアント申告を信用せず、サーバー内台帳から参加可否・差引・賞金反映を行う
- フェーズ世代番号で古い操作を拒否
- 経済操作に操作IDを付け、ACK再送時の二重処理を抑止
- 交換提案側の資産をエスクローし、拒否・取消・期限切れで返却
- 交換提案は同時件数制限なし。同一相手への複数提案・複数相手への並行提案に対応。1提案内でカード枚数も指定可能
- 交換承認は必要資産を検証・確保してから操作IDを確定
- 秘密目標欠損はstate送信前に自動修復
- 他人のHP/ポイント/手札/特殊/秘密目標/賭け情報を必要以上にsnapshotへ含めない
- 個別チャットは当事者だけへ配信
- 公開結果廃止後の内部対戦ログはクライアントへ配信しない
- CSP / HSTS(本番) / frame拒否 / no-referrer / Permissions-Policy
- Socket総接続数・ルーム数・入力長・操作頻度を制限
- ルームコードと初期配布に暗号学的乱数を使用
- 終了画面描画後はWebSocketを解放

## パフォーマンス

5人固定のため、ゲーム処理はサーバー内の小さな同時解決です。通常stateは軽量化し、静的カード/目標定義は初回stateだけ、チャットは差分配信、内部対戦ログは送信しません。カード画像はリビジョンURL＋長期キャッシュ、待機中に先読みします。

現在の状態は単一Nodeプロセスのメモリ保持です。試合状態と五戯チップ台帳は同一プロセス内で管理します。最初の小規模公開では1インスタンスを前提とし、水平分散や再起動復元は意図的に未実装です。

## 起動

Node.js 24.21.xを推奨します。`package.json` は `>=24.21.0 <25` を指定しています。

```bash
npm install
npm run verify
npm start
```

本番では `.env.example` を基に、少なくとも `NODE_ENV=production` と正しい `ALLOWED_ORIGINS` を設定してください。

### 五戯チップのアカウントレス設計上の限界

ブラウザが送る残高値は信用せず、実行中サーバーの台帳を正とします。そのためlocalStorageの残高数字を書き換えるだけでは増やせません。ただし恒久アカウント/DBがないため、ブラウザ識別子を消去して新規ブラウザ扱いにする行為や、サーバー再起動をまたぐ残高保持までは保証しません。実価値を付与する場合は認証＋永続DBが必須です。

- 準備OK中でも公開契約・交換通知を受信。交換提案は接続中の人間のみ準備OKを自動解除して回答を要求し、公開契約は自動参加のため準備OKを維持する。
